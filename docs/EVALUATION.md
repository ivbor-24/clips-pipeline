# Оценка против эталонного набора

> Как измерить, что изменение скоринга, промптов или транскрибации сделало клипы
> лучше, а не просто «не уронило» пайплайн: прогнать набор видео, для которых
> уже есть шорты, вырезанные вручную, и сравнить клипы пайплайна с ними и с
> прошлым прогоном.

## Эталонный набор

Набор собираете вы сами из своих видео; в репозиторий он не попадает. Это
каталог с исходными видео (эпизодами) и файлом `manifest.json`, который
описывает, какие шорты из них уже вырезаны вручную и где в исходнике их куски:

```json
{
  "episodes": {
    "lecture_1": {
      "path": "/data/reference/lecture_1.mp4",
      "size_bytes": 3512345678,
      "sha256": "…",
      "duration_sec": 5439
    }
  },
  "shorts": [
    {
      "id": "lecture_1_short_1",
      "episode": "lecture_1",
      "pieces": [
        {"source_start": 812.4, "source_end": 851.0, "short_start": 0.0, "short_end": 38.6},
        {"source_start": 859.2, "source_end": 893.5, "short_start": 38.6, "short_end": 72.9}
      ],
      "structure": {"montage": false}
    }
  ],
  "pipeline_clip_labels": [
    {"episode": "lecture_1", "source_start": 1203.0, "source_end": 1281.5, "label": "keep"}
  ]
}
```

- `episodes`: id эпизода → `path` (абсолютный путь к файлу), `size_bytes`,
  `sha256`, `duration_sec`.
- `shorts`: шорты, вырезанные вручную. Каждый — список `pieces` (кусков
  исходника): `source_start`/`source_end` (секунды в эпизоде) и
  `short_start`/`short_end` (положение в шорте). `structure.montage: true` —
  тизер, склеенный из далёких мест: пайплайн такие не делает, в метрику Hit они
  не входят. Для шортов с переставленными кусками — `structure.reordered: true`
  и `structure.source_span` (начало и конец всего фрагмента в исходнике).
- `pipeline_clip_labels` (необязательно): прошлые оценки клипов пайплайна
  (`source_start`, `source_end`, `label` = `keep` | `edit` | `reject`).

Пайплайн вырезает один непрерывный кусок 45–90 с на клип, а ручные шорты часто
состоят из 2–7 кусков с вырезанными частями. Поэтому метрики считаются по
перекрытию по времени в исходнике, а не по точным границам. Совпадение с ручным
выбором — не то же самое, что качество: хороший клип может стоять в другом
месте выпуска. Главная мера — доля `keep` среди оценённых в Review.

## Команды

Сервис должен быть запущен (`just up`); скрипт ходит к нему по HTTP, как
веб-интерфейс (логин, загрузка, задачи, оценки). Используется `python3` хоста,
Docker-Python-окружение не нужно.

```bash
# Прогнать пайплайн по всем эпизодам набора
just eval run --set /path/to/manifest.json --label baseline

# Только некоторые эпизоды, с переопределением конфига и проверкой sha256
just eval run --set /path/to/manifest.json --label baseline \
  --only EP_1 EP_2 --overrides overrides.json --verify-sha

# Отчёт по прогону
just eval report --set /path/to/manifest.json baseline

# Сравнить два прогона
just eval report --set /path/to/manifest.json experiment --against baseline
```

`run` проверяет, что исходник существует и его размер совпадает с `size_bytes`
(sha256 — только с `--verify-sha`, файлы гигабайтные), загружает его через
эндпоинт загрузки (потоком, не читая целиком в память), создаёт задачу клипов с
настройками по умолчанию или из `--overrides` и ждёт завершения. Повторный `run`
с тем же `--label` **продолжает**: эпизоды с завершённой задачей пропускаются.
Ctrl+C оставляет задачи в работе, а файл прогона — продолжбой: запустите `run`
с тем же лейблом ещё раз, и он дождётся уже запущенных задач.

`report` берёт статусы Review у задач прогона (keep/edit/reject/pending) и кладёт
их в файл прогона.

## Метрики

- **Coverage** — доля исходного материала шорта (сумма длительностей его кусков),
  которую покрывает клип; считается сумма перекрытий клипа с каждым куском,
  делённая на общую длительность кусков.
- **Hit** — шорт «найден», если лучший по покрытию клип того же эпизода даёт
  coverage ≥ `--hit` (по умолчанию 0.5). Считается найденных / всего по эпизодам
  и суммарно, плюс список ненайденных с их лучшим покрытием. Тизеры (montage)
  не участвуют.
- **Hook** — для найденного шорта: начинается ли совпавший клип в пределах
  ±`--hook-sec` (по умолчанию 3 с) от начала первого куска шорта (кусок с
  минимальным `short_start`). Для `reordered` шортов дополнительно — в пределах
  ±`--hook-sec` от `structure.source_span[0]`.
- **Precision** — доля клипов прогона, которые находят хотя бы один нетизерный
  шорт (coverage ≥ порога Hit) или имеют временной IoU ≥ 0.5 с оценкой
  `keep`/`edit` из `pipeline_clip_labels`.
- **Labels** — по размеченному эпизоду: клипы с IoU ≥ 0.5 с оценкой `reject`
  (ошибки) и с `keep` (хорошие), списки id.
- **По эпизодам** — число клипов, медианная длительность клипа, счётчики статусов Review и доля `keep` среди
  оценённых.

Прогон с упавшими задачами или непросмотренными клипами всё равно выводится —
с предупреждением сверху о том, что именно неполное.

## Перенос оценок между прогонами

Просматривайте клипы на странице Review (`keep` / `edit` / `reject`). Чтобы не
оценивать заново те же клипы после перескоринга:

```bash
just eval carry-over experiment --from baseline --iou 0.8
```

Каждому клипу прогона `experiment` со статусом `pending`, чей временной IoU с
оценённым клипом `baseline` того же эпизода не меньше `--iou`, ставится та же
оценка с заметкой `carried over from baseline (IoU 0.87)` (жадное сопоставление
по лучшему IoU, один к одному). Скрипт печатает, сколько перенесено и сколько
осталось оценить.

| Что | Куда |
|---|---|
| Прогон | `eval/runs/<label>.json` |
| Отчёт | `eval/reports/<label>.md` |
| Каталог `eval/` | в `.gitignore`, в репозиторий не попадает |
