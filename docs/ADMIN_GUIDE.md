## 1. Установка и требования к железу

Установка — одной командой `./setup.sh` (см. [INSTALL.md](INSTALL.md), разделы
«Что нужно на хосте» и «Установка»). Скрипт проверяет Docker, находит GPU,
пишет `.env`, собирает образы, скачивает модели и запускает систему.

Что нужно на машине:

| Ресурс | Сколько | Зачем |
|---|---|---|
| Диск | ~25 ГБ | образ ~5 ГБ, модели ~11 ГБ, задачи |
| Видеопамять | ~10 ГБ | локальная LLM Qwen3-14B; без неё — API-провайдер |
| Память | от 8 ГБ | пиковое потребление на лекции 25 мин — ~8 ГБ |

Клипы выбирает LLM, без неё установка не завершается: `setup.sh` скачивает
Qwen3-14B или подключает API-провайдера (OpenAI, Anthropic или сервис с
OpenAI-совместимым API) — см. [INSTALL.md](INSTALL.md), шаг 6. На видеокарте
меньше 12 ГБ и без видеокарты локальная LLM работает очень медленно: `setup.sh`
предупредит об этом и по умолчанию предложит API. Поддерживаемое железо — в разделе
[«Матрица поддержки»](#10-матрица-поддержки).

## 2. Обновление

```bash
git pull
./setup.sh        # пересборка и новые модели; настройки сохраняются
```

Подробности (что переживает обновление, схема БД, очистка кэша сборки) — в
[INSTALL.md](INSTALL.md), раздел «Обновление». Перед обновлением существующей
базы рядом остаётся копия `data/api.db.before-<ревизия>`.

## 3. Запуск, остановка, состояние

```bash
just up      # запустить (http://127.0.0.1:8080)
just stop    # остановить; задача в работе вернётся в очередь
just status  # что запущено, адрес, версия
```

Есть и выключение из интерфейса (кнопка **Shut down**) и автовыключение при
простое (по умолчанию 60 минут). Полный список проверок `just up` и поведение
при перезагрузке — [INSTALL.md](INSTALL.md), раздел «Запуск, остановка,
состояние».

## 4. Доступ из локальной сети и пароль

Настройки в `.env` (их заполняет `./setup.sh`):

- `BIND_ADDRESS` / `WEB_PORT` — на каком адресе слушает интерфейс. По умолчанию
  `127.0.0.1` — только эта машина.
- `API_PASSWORD` — общий пароль; без него входа нет. Перед открытием доступа в
  локальную сеть (`BIND_ADDRESS=0.0.0.0`) пароль обязателен.
- `API_JWT_SECRET` — генерируется `setup.sh`, нужен только при пароле.
- `API_ALLOWED_HOSTS` — имена хостов, по которым API отвечает без пароля
  (защита от DNS rebinding).

Подробности в `.env.example` и [INSTALL.md](INSTALL.md), раздел «Если что-то не
так» (ошибка «Unknown host name» / 403).

## 5. Где лежат данные и что из этого важно

Каталоги в корне проекта. Важны для бэкапа — `data/`, `.env` и (по желанию)
`jobs/`:

| Каталог | Что в нём | Важно? |
|---|---|---|
| `data/` | база задач и оценок клипов (`api.db`), ваши настройки со страницы Settings (`settings.yaml`) | да — история задач и настройки |
| `jobs/` | рабочие каталоги задач: клипы, субтитры, артефакты | да, если жалко готовые клипы |
| `config/` | настройки пайплайна по умолчанию (`config.yaml`, профили) | нет — приходят с кодом; ваши изменения — в `data/settings.yaml` |
| `uploads/` | загруженные видео | нет — восстанавливаемо |
| `cache/` | кэш транскрипций (14 дней) | нет |
| `MODELS_DIR` (по умолчанию `./models`) | веса моделей (~11 ГБ) | нет — скачиваются заново |
| `backups/` | архивы `just backup` | — |

Готовые клипы задачи лежат в `jobs/job_<id>/output/clips/` (mp4 + srt). Модели
в бэкап не входят: их снова скачает `./setup.sh`.

## 6. Бэкап и восстановление

```bash
just backup                    # база, data/settings.yaml, .env, каталоги задач без исходников
just backup --with-sources     # то же с исходными видео (~2 ГБ на лекцию)
just restore backups/backup-<дата>.tar   # только при остановленной системе
```

Ограничения (что `.env` не заменяется, куда кладётся копия) — [INSTALL.md](INSTALL.md),
раздел «Хранение, удаление и бэкап».

## 7. Автоочистка и срок хранения

Через `cleanup.retention_days` (по умолчанию 30) дней после завершения задачи
удаляется её исходное видео (~2 ГБ на лекцию); клипы, оценки и карточка
остаются, но Resume закрыт. Загрузки без задачи удаляются через сутки. Срок
меняется на странице Settings (`cleanup.retention_days`, `0` — не удалять).
Подробности — [INSTALL.md](INSTALL.md) и [CONFIG.md](CONFIG.md), секция
`cleanup`.

## 8. Логи и проверка GPU

- **Контейнеры:** `docker compose logs -f worker-openvino` (или `worker-cuda`,
  `worker-cpu`).
- **Лог задачи:** панель Logs на странице задачи, всегда доступна после
  завершения.
- **Проверка GPU:** страница **Diagnostics** веб-интерфейса (или
  `docker compose run --rm worker-openvino python scripts/check_gpu.py
  --backend openvino`). Кнопка **Copy report** собирает отчёт для вопроса.
- **Типичные проблемы:** [INSTALL.md](INSTALL.md), раздел «Если что-то не так»
  (ошибки `setup.sh`, 403/Unknown host, нет интернета у контейнеров, GPU не
  используется, файлы принадлежат root).

Режим без Docker (для разработки и командной строки, после `./install.sh`) —
[INSTALL.md](INSTALL.md), раздел «Без Docker».

## 9. Оценка качества против эталонного набора

Чтобы измерить, что изменение скоринга или промптов сделало клипы лучше (а не
просто «не уронило» пайплайн), есть скрипт оценки против набора шортов,
вырезанных вручную: `just eval run/report/carry-over` (`scripts/evaluate.py`).
Как собрать свой набор, что значит каждая метрика и как сравнивать прогоны —
[EVALUATION.md](EVALUATION.md).

## 10. Матрица поддержки

Статусы: **проверено** — установка и задачи выполнялись на реальной машине;
**собирается** — сборка образа проходит (`docker-cuda.yml`, `just check-cuda-image`), на реальной карте не запускалось;
**без гарантий** — должно работать, не проверялось; **не поддерживается** —
не работает по замыслу.

| Платформа | Статус | Примечание |
|---|---|---|
| Ubuntu (Docker, CPU) | проверено | смоук-тест установки с нуля (`scripts/docker_smoke.sh`) на раннере GitHub `ubuntu-latest` (`docker-smoke.yml`, запускается вручную) |
| CachyOS / Arch-based, ядро 7.x (Docker) | проверено | машина разработки: установка `setup.sh`, обновление, полные задачи, Quick Sync, VAAPI-декодирование |
| NVIDIA (CUDA) | собирается | образ собирается (`docker-cuda.yml`, `just check-cuda-image`), на реальной карте не запускался: машины с NVIDIA у проекта нет — отчёты о работе на NVIDIA очень помогут. Требования: драйвер ≥ 525, NVIDIA Container Toolkit, compute capability карты в `CUDA_ARCHITECTURES` (по умолчанию 75;80;86;89;90;120 в `Dockerfile.backend`) |
| Intel Arc B580 (Vulkan) | проверено | llama.cpp / whisper.cpp через Vulkan (Mesa), видео через VA-API / Quick Sync |
| Встроенная графика Intel, прочие поколения Arc | без гарантий | не проверялось |
| AMD (ROCm) | не поддерживается | установка идёт на CPU |
| CPU без GPU | без гарантий | работает, но выбор клипов Qwen3-14B — часы на видео; рекомендуется API-провайдер |
| Остальные дистрибутивы Linux | без гарантий | официальная цель — Ubuntu; проверены Ubuntu (раннер GitHub) и CachyOS |

Ограничение платформы: только Linux, официально — Ubuntu. Windows и macOS не
поддерживаются.
